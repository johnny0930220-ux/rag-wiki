# 擷取筆記：第 7 週投影片《讓 AI 看懂你的世界》

> 本檔整理自課堂投影片，頁碼寫成 p.12。投影片版權屬於授課老師，這裡只放改寫後的重點。

## RAG 就是 Context Engineering（p.3–5）

- 寫 prompt 要給「正確的資訊」和「清楚的指引」。RAG 是把「正確的資訊」改成讓電腦自己去找。
- 老師強調要理解原理，不要被大字彙嚇到。

## Embedding 模型（p.6–9）

- 關鍵是 embedding 模型：把一段文字轉成一個向量，代表這段文字抽象的意思。它本質上也是語言模型。
- 常用對比學習訓練：問題和正確段落的向量越近越好，和不相關段落越遠越好。例子：「圖書館星期日幾點關門？」應該靠近「本館週日開放至下午五點」，遠離「本館借書期限為三十天」。
- 有些模型會加 `query:`、`passage:` 前綴，但沒有通用寫法。

## 怎麼切資料（p.10–16）

- 傳統做法：把檔案放進一個資料夾，自動切成固定長度的文字塊，例如每塊 500 字、重疊 50 字。
- 要考慮的事：塊要多大、要不要依條文切、要重疊多少。
- 較新的做法：自己切成想要的樣子。每份文件分成「拿去做 embedding 的文字」和 metadata（標題、來源網址、日期、分類）。metadata 可以拿來做關鍵字搜尋或篩選。

## RAG 的流程（p.17–24）

1. 每份資料用 embedding 模型算出代表向量，存成向量資料庫。
2. 使用者的問題也轉成向量。
3. 找出和問題最接近的資料；通常不只一筆，可能要重新排序（reranking），或把前後文一起拿進來。
4. 把找到的資料和原始問題放進新的 prompt，例如「請根據 {retrieved_chunks} 裡的資訊，回應使用者的問題：{question}」。

## 真的需要 RAG 嗎？（p.26–28）

- 模型能讀的上下文越來越長，全部放進 prompt 也是一種做法。
- CAG：用 KV-Cache 技術先把資料的鍵值存起來，直接交給 LLM。

## LLM 的記憶（p.30–34）

- 短期記憶就是這次的對話，下次就忘了，對話太長也會忘記前面。
- 長期記憶的一種做法，是把過去的對話做成向量資料庫，也就是 RAG。

## LLM Wiki（p.36–46）

- 2026 年 4 月 Karpathy 分享的做法：把來源放進 `raw/`，讓 LLM「編譯」成一系列 Markdown 頁面，包含摘要、反向連結和概念文章。
- wiki 夠大（約 100 篇、40 萬字）時可以問複雜問題。他原本以為需要複雜的 RAG，但 LLM 自己維護的索引和摘要就夠用了。
- 答案可以輸出成 Markdown、投影片或圖表，再歸檔回 wiki；也會請 LLM 健檢，找出不一致或缺漏。
