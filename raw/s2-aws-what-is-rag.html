# 擷取筆記：AWS〈What is RAG?〉

本檔是讀原文後整理的擷取筆記，不是全文轉貼。

定義

  • RAG 讓大型語言模型在回答前，先參考訓練資料以外、具權威性的知識庫（原文："references an authoritative knowledge base outside of its training data sources"）。
  • 不需要重新訓練模型，就能把 LLM 延伸到特定領域或組織內部知識。

LLM 已知的問題

LLM 的輸出不一定可預測，而且訓練資料是靜態的、有截止日期。AWS 列出的問題：

  1. 不知道答案時給出錯誤資訊。
  2. 使用者要具體、最新的答案時，給出過時或籠統的資訊。
  3. 從不具權威性的來源產生回答。
  4. 不同訓練來源用同一個詞指不同東西時，產生不正確的回答。

比喻：LLM 像一個「過度熱心的新員工」，不看最新消息，卻每個問題都很有自信地回答。

RAG 的好處

  • 成本較低：為組織資料重新訓練基礎模型很貴，RAG 是比較便宜的加入新資料方式。
  • 資訊較新：可以接上經常更新的來源，例如新聞網站。
  • 提高信任：回答可以附上來源或引用，使用者能回頭查原始文件。
  • 開發者更能掌控：可以更換資料來源、依權限限制敏感資料，並修正引用錯誤來源的情況。

RAG 怎麼運作（四個步驟）

  1. 建立外部資料：把 API、資料庫或文件庫裡的新資料，用 embedding 模型轉成數字表示，存進向量資料庫。
  2. 檢索相關資訊：把使用者的問題轉成向量，和資料庫比對。例子是 HR 聊天機器人：員工問「我還有多少年假？」，系統會找出年假政策文件和這位員工過去的請假紀錄。
  3. 擴增 prompt：把找到的資料當作上下文加進使用者的 prompt，讓 LLM 能正確回答。
  4. 更新外部資料：文件和 embedding 要持續更新，可以即時自動處理或定期批次處理。

RAG 和語意搜尋

  • 企業資料分散在手冊、FAQ、研究報告、人資文件等系統裡，要大規模找到對的內容很難。
  • 傳統關鍵字搜尋在知識密集任務上效果有限，開發者還要自己處理 embedding 和切塊。
  • 語意搜尋能把問題對應到相關文件、回傳特定段落，並依相關程度排序，提升 RAG 的輸入品質。例子：「去年機器維修花了多少錢？」
