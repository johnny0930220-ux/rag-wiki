## 兩個階段

IBM 把 RAG 分成兩個階段：先檢索出相關片段，再把片段附加到 prompt 裡讓 LLM 生成回答。[S4]

## 四個步驟

AWS 把流程拆成四步：[S2]

1. 建立外部資料：把文件用 embedding 模型轉成向量，存進向量資料庫。[S2]
2. 檢索相關資訊：把使用者的問題也轉成向量，去資料庫比對。[S2]
3. 擴增 prompt：把找到的資料加進使用者的 prompt。[S2]
4. 更新外部資料：文件和向量要定期或即時更新。[S2]

NVIDIA 描述的流程相同，並補充最後 LLM 可以在回答中附上來源；開源函式庫 LangChain 常用來把這些元件串起來。[S3]

課堂投影片的版本多了「切塊」：先把資料切成文字塊，每塊算出向量；找到的資料通常不只一筆，可能還要重新排序。[S6]

## 例子

AWS 的 HR 機器人：員工問「我還有多少年假？」，系統找出年假政策文件和這位員工的請假紀錄，再交給 LLM 回答。[S2]
