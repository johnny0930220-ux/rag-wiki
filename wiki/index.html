# RAG Wiki 索引

這個 wiki 整理 6 篇關於 RAG（檢索增強生成）的資料。每個概念一頁，內文都標了來源 S1～S6。

入門

  • RAG（檢索增強生成） RAG（檢索增強生成）：讓大型語言模型回答前，先從外部資料找出相關內容，再根據這些內容回答。
  • 大型語言模型（LLM） 大型語言模型（LLM）：用大量文字訓練、把知識存在參數裡的模型，例如 ChatGPT 背後的模型。
  • LLM 的限制 LLM 的限制：LLM 的知識有截止日期、可能過時或錯誤，也很難說出知識的出處。
  • 幻覺（hallucination） 幻覺（hallucination）：模型給出聽起來合理、但其實是錯誤的答案。RAG 能降低，但不能消除。
  • 理解 RAG 的比喻 理解 RAG 的比喻：開書考、法院書記官、過度熱心的新員工，三個幫助理解 RAG 的比喻。

RAG 怎麼運作

  • RAG 的運作流程 RAG 的運作流程：準備資料、把問題轉成向量去找資料、把資料放進 prompt、讓 LLM 回答。
  • 切塊（chunking） 切塊（chunking）：把長文件切成一小塊一小塊再做 embedding；切法會影響找不找得到。
  • Embedding（向量表示） Embedding（向量表示）：把一段文字轉成一串數字（向量），意思相近的文字，向量也會靠近。
  • 向量資料庫 向量資料庫：存放大量文字向量、能快速找出和問題最接近的資料庫。
  • 檢索（retrieval） 檢索（retrieval）：根據使用者的問題，從資料庫找出最相關的幾段資料。
  • 擴增 prompt 擴增 prompt：把找到的資料和使用者的問題一起放進新的 prompt，交給 LLM 回答。
  • 附來源與信任 附來源與信任：RAG 的回答可以附上資料來源，讓使用者自己查證。

限制與替代做法

  • RAG 的限制 RAG 的限制：RAG 不完美：仍可能幻覺、不會自己承認不知道，而且找不找得到資料也是問題。
  • 直接放進 prompt（長上下文與 CAG） 直接放進 prompt（長上下文與 CAG）：資料不多時，不必檢索，直接把全部資料放進 prompt。
  • LLM Wiki LLM Wiki：讓 LLM 自己把來源整理成 Markdown 知識庫，再用這個知識庫回答問題。

進階檢索技巧

  • BM25 與混合搜尋 BM25 與混合搜尋：用字詞比對找精確字串，和 embedding 的語意搜尋互補。
  • Contextual Retrieval Contextual Retrieval：替每個文字塊補上一段上下文，再做 embedding 和 BM25，降低找不到的機率。
  • Reranking（重新排序） Reranking（重新排序）：先多找一些候選資料，再用另一個模型重新評分，只留最相關的。
